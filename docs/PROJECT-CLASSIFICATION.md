# 项目定性与技术边界

## 一句话结论

这是一个 **AI 应用开发项目**，产品形态是面向个体商家的 **本地优先、审核优先的电商研究与内容生产工作台**。它包含 AI 产品能力，但当前不是一个已经可以自主经营店铺的 Autonomous Commerce Agent。

当前工作台有两个主模式：

1. **选品洞察**：根据用户需求和产品大类，收集公开商品详情页，比较价格、页面声明的性能/规格、重量、评论数量、好评、差评、差评率口径和差异化配置。
2. **爆款复刻**：由用户在已登录的抖音/TikTok 前台记录参考候选，按已输入播放量排序，结合授权的本地参考视频、商品素材和商品事实，生成镜头拆解与 Hypit 交接包。

## 技术分类

| 技术 | 当前状态 | 实际位置 |
|---|---|---|
| AI 应用开发 | 已有 | Node HTTP 服务、浏览器工作区、模型调用、结构化输出、审核门 |
| Prompt engineering | 已有 | `lib/prompt.js` 的平台写作规则、事实约束、可信度契约和情报解释 Prompt |
| Context engineering | 已有 | 将商品事实、来源、观察时间、产品/SKU、素材角色、权利和禁止事项组织成受限上下文 |
| Agent orchestration | 内核已有，业务入口受限 | `lib/commerce/orchestrator.js` 的有限角色/工具 DAG、权限、预算、租约、幂等、取消和恢复 |
| Agent loop | 有受控执行循环，不是开放式自主循环 | worker 按计划节点执行、检查边界、记录事实和质量门；不会自行扩展工具或目标 |
| Skills 文档 | 已有外部交接边界 | `docs/VIDEO-WORKBENCH.md` 与 Hypit skill 文档定义参考笔记、Brief、工程和 Build Results 的交接关系 |
| RAG | 当前没有 | 没有向量数据库、embedding 检索或知识库问答；公开页面研究是确定性抓取/解析 |
| MCP | 当前没有作为主链路 | 没有依赖 MCP server；未来可将浏览器、文件、检索或 Hypit Runtime 封装为受权限控制的工具 |
| LangChain | 当前未引入 | 现有 Node 模块和确定性工作流已满足需求；引入前需证明 tracing、tool routing 或 provider portability 的收益 |
| 多模态 | 局部已有 | 内容生成支持图片输入；视频工作台目前只做本地预览、切点候选和人工/外部分析交接 |
| 数据治理 | 已有 | 来源、观察时间、字段口径、任务级输出、隐私策略、独立审核和 fail-closed 边界 |

## 当前 Agent 到底做什么

模型调用目前是请求/响应服务：

- `/api/generate`：根据已提交事实生成多平台图文草稿；
- `/api/intel/interpret`：根据已计算的本地情报生成摘要、置信度、限制和建议；
- 其他产品研究、价格/重量/评论/特征提取主要是确定性代码，不是模型自主判断。

Agent 内核负责的是受控执行，而不是自行经营：

- 只能运行预先注册、带 Schema 和角色白名单的工具；
- 每个运行有项目/任务范围、预算、租约、幂等键和取消状态；
- 外部工具需要 payload/context 隐私白名单和权限；
- 结果要经过证据、质量和审核边界；
- 公共任务中心当前只开放合成 `fixture-echo.v1`，不开放自动登录、改价、发布、消息、支付或视频付费生成。

## 选品模式的证据边界

`POST /api/sourcing/insights` 只面向 Amazon.com 公开前台。它可以返回：

- PDP 价格、品牌、标题、图片、尺码、产品尺寸和 Item Weight；
- 商品详情页 bullet 作为“页面声明”的性能/功能证据；
- 评分、评论数量、可见好评/差评样本、评论问题主题；
- 公开星级分布可用时的 1–3 星比例；没有分布时，明确标记为可见评论样本比例；
- 头盔等品类的头灯、护目镜/MIPS、电池、认证等特征出现情况。

它不返回：

- 供应商成本、真实销量、后台销售额或利润；
- 未读取页面中的参数；
- 把评论样本比例说成全部评论差评率；
- 把产品特征出现率直接说成市场机会或推荐结论。

## 爆款复刻模式的证据与权限边界

播放量排序基于用户从已登录抖音/TikTok 搜索页输入的候选，排序结果的语义是“用户输入候选中的最高播放量”，不是平台全量最高。参考来源只作为元数据保存；本应用不自动绕过登录、下载、上传、付费生成或发布。

可迁移的是结构：钩子、镜头长度、切点密度、景别/机位、信息顺序、口播节奏和氛围。必须重建或重新核验的是商品画面、人物、声音、音乐、Logo、参数、价格、功能声明和发布权限。

## 为什么现在不需要 RAG、MCP 或 LangChain

当前主要问题是数据边界、页面证据、人工确认和外部执行权限，而不是长文档语义召回。公开 PDP 字段应保留原始来源和观察时间，直接结构化比向量召回更可审计。Agent 工具数量和执行范围尚未达到必须引入 LangChain 或 MCP 的程度；如果未来连接浏览器检索、转录、Hypit Runtime 或平台发布，应先把每个外部能力定义为独立工具，再通过权限、预算、作用域、幂等和审核门接入，而不是先引入框架。

## 定位

最准确的产品定位是：

> **AI-assisted, evidence-governed commerce workbench with a governed Agent kernel**

中文可称：

> **带受控 Agent 内核的证据治理型电商研究与内容生产工作台**
